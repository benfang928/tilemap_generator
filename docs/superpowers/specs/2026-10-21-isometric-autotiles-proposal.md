# 传奇矩形地砖、斜视美术与自动过渡：设计提案

状态：用户已认可第三种方案“统一接缝 + 自动过渡”，并明确传奇为右上斜视美术、矩形地砖格。设计以实际客户端的 48×32 矩形逻辑格为约束，不增加菱形投影。本轮已更新独立交互原型；主程序的生成、提取、渲染尚未接入本设计。

## 问题与目标

当前地砖是独立生成的正方形图块，同类变体的边缘不共享约束；程序按类别随机替换，导致亮度、纹理及地形边界突变。Web 渲染与鼠标拾取均使用正方形网格，封边仅替换为岩地，不含直边、凸角、凹角规则。

目标是输出可连续拼接的矩形地砖，支持斜向边界、内外拐角和自动选砖，并允许设置地砖素材像素尺寸、基础变体数量、前景数量及前景槽位尺寸。斜视美术与矩形存储分别处理。

## 推荐路线

保留“地形、前景”两类源图集。AI 生成同风格、同视角、同纹理尺度的基础材质和独立物件；程序负责纹理周期化、边缘一致化及自动连接砖烘焙。先在连续地面上合成地形和边界，再切为矩形帧，避免每块砖各自构造斜边。

不要求 AI 在一次生成中严格画对几十种连接状态。也不把随机抽取的不同纹理视作天然能互相拼接。

替代方案：让 AI 直接画完整连接砖图集，艺术表现更自由，但格位及边缘容易出错；只生成一种纹理重复平铺，容易控制接缝，但无法满足材质变化与转角要求。

## 客户端坐标、尺寸与锚点

- 逻辑格固定 48×32，坐标按 `screenX = x * 48`、`screenY = y * 32` 落位（另加相机平移）。不旋转、错列或剪切网格；右上斜视效果由美术里的建筑轴线、物件侧面、地面纹理及场景布局表达。“45 度”不直接转换成网格的数学投影角。
- 当前客户端底层在正偶数 x/y 坐标绘制底砖，典型素材为 96×64，覆盖 2×2 逻辑格。单格过渡优先合成进这些底砖；需要独立中层时输出客户端接受的 48×32 或 96×64 帧。底图有效区留出客户端跳过的零行/零列，并验证外围封边。
- 每张素材分别记录 `sourceSize`、`frameSize`、`footprintCells`、`anchor`。用户选择高分辨率素材不会改变寻路/碰撞格；客户端底层仍烘焙为 96×64。多格底砖内部也可以包含四个不同语义格的过渡。
- 前景画布可为 256×384，占地仍可能只有一格。脚底锚点、碰撞占地及美术外伸范围独立；物件保持原宽高比，不能随地面压扁。Web 按落地点 y/x 的顺序绘制，并与客户端遮挡用例对照。
- 当前客户端普通静态前景以 `(x * 48, (y + 1) * 32 - imageHeight)` 绘制。`MLibrary.Draw(int,int,int)` 不自动应用帧偏移；带 `Point` 的部分重载在 `offSet=true` 时才应用偏移。因此常规静态物件应在烘焙画布中对齐约定落点，不能假定写入偏移即可生效。
- Web 绘制、拾取、网格、选区、缩放定位及 PNG 导出共用矩形坐标规则。旧正方形工程保留原坐标设置，迁移必须显式记录，不能仅更改显示标签。

核对依据（父仓库只读）：`Client/MirScenes/GameScene.cs` 的 `CellWidth/CellHeight`、`DrawFloor` 和静态前景绘制分支；`Client/MirGraphics/MLibrary.cs` 的 `GetOffSet` 及 `Draw` 重载。WPF 中名为 `IsometricRenderer` 的类同样使用矩形映射，类名不作为投影依据。

## 连续材质与自动连接

1. 每种地形生成基础纹理，统一纹理尺度、色调和光照；明确为传奇斜视游戏地面、无独立浮空菱形边框。按目标矩形比例生成，在逻辑纹理空间合成；不把已有正方形图压扁当作正式美术。
2. 对基础纹理做周期化处理；同类变体使用共同边缘和角点约束，主要在内部变化。必须额外校验不同变体互相相邻时的接缝。
3. 用八邻域掩码确定连接状态；仅在两个相邻正交方向连通时考虑其对角，归一化为标准 47 种 blob 状态。包括孤立块、窄连接、端头、直边、凸角、凹角及全填充。
4. 草地作为基础层，合成顺序固定为水域→土路→岩地。遮罩在连续地面坐标里构造并保留采样边距，再切片，斜向岸线和道路不能逐格独立修边。多材质交会与 2×2 底砖内部交界使用相同规则。
5. 地图保存语义地形与变体种子，连接砖索引由邻居推导。画笔修改后刷新附近连接状态；撤销、重做、载入和导出使用相同规则。
6. 碰撞由地形及物件占地决定，透明过渡边不能直接等同于阻挡范围。

47 状态用于平面区域边界。立体城墙、悬崖另有墙面、高度、端头及转角规则，不能把平面纹理拉伸后宣称完成立体封边。第一阶段覆盖平面岩地/岸线封边；立体墙体作为单独阶段实现，开始前明确选择。

## 图集配置

| 参数 | 建议默认 | 含义 |
| --- | --- | --- |
| 地砖素材输出尺寸 | 96×64 | 可选 48×32、96×64、192×128、384×256；与客户端运行帧尺寸分别记录 |
| 逻辑格 / 客户端底砖 | 48×32 / 96×64 | 底砖覆盖 2×2 格；素材分辨率不改变逻辑格 |
| 地形种类 | 草地、土路、水面、岩地 | 各类含行走属性与过渡目标 |
| 每类基础变体 | 8 | 可调整，所有变体遵守同一边缘约束 |
| 连接状态 | 自动生成 | 不占用户设置的基础变体数量 |
| 前景数量 | 24 | 支持 0–64，数量与地图上的摆放密度分开 |
| 前景槽位 | 256×256 | 可选方形或竖长画布，默认等比适配、不裁主体 |
| 前景清单 | 按主题预填 | 可编辑名称、类别、占地和阻挡属性 |

用户所设像素尺寸是本地切片/烘焙的输出规格，不能承诺模型天然返回该精度。页面展示请求尺寸、实际源图尺寸与输出尺寸；源图精度不足时提示重生或拆页，避免把放大后的图片描述成新增细节。

图集网格由槽位尺寸、数量与接口最大图尺寸计算，不再写死 4×4、4×2。槽位保存角色和裁切坐标，不依赖图中文字识别。大数量按页生成并分别重试；两类图集可以包含多页，界面提前展示请求次数。留出切片间隔与安全边距，导出精确 frame 和 anchor 元数据。

## 验证与交付顺序

先用确定性的本地材质验证连续接缝、矩形坐标与自动连接，再接入真实生成，避免把算法错误与模型误差混在一起。独立预览复用旧图片，仅演示规则与比例，不作为最终斜视美术样例。

1. 48×32 绘制/拾取往返、96×64 底砖奇偶落位、零行/零列边界、前景脚底及遮挡、PNG 导出一致性；旧正方形工程兼容。
2. 同材质重复和混合变体的 8×8 平铺预览；直边、凸角、凹角、单格、窄路、斜向道路、斜向岸线与多材质交点测试板；跨 2×2 底砖接缝及透明裂缝检查。
3. 动态图集尺寸、前景 0/1/24/64、不同长宽比、空槽、部分页失败与重试。
4. 编辑时邻域重算、撤销/重做、保存加载、旧正方形工程兼容，以及导出元数据完整性。

接缝数值检查不能替代实际大小下的视觉检查，地形过渡形状也不能仅靠增加槽位数量解决。最终示例应同时包含重复铺砖、复杂边界和完整地图。

## 客户端导出边界

当前 Web 的 `.map` 导出尚未完成实际素材库绑定：客户端 `BackIndex` 表示素材库号，`BackImage` 的低位表示帧号加一，碰撞标志另存高位。仅把材质编号写进 `BackIndex` 并设置碰撞位，不能显示地面。需交付“库号/帧号映射 + 可供客户端读取的素材库 + 地图”，并在客户端验证，才能称为可用地图。此阶段先完成 Web 拼接、切片 PNG 及精确元数据；客户端库打包作为后续独立集成阶段，不把当前 `.map` 按钮视为兼容性验收。
