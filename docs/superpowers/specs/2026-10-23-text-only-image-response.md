# 生图接口返回文字的排查记录

用户现象：生成 1024×1024、100 槽位地下城地砖图集时，收到 HTTP 400。错误正文是规格说明、能力限制说明和 `<FollowUp ... />` 建议，没有图片。

## 已确认的边界

- 本地 `/proxy` 转发上游状态和响应体，不生成 FollowUp，也不把成功状态改为 400。
- 浏览器 `postJSON` 在非成功 HTTP 状态时直接抛错；此次 400 不发生在裁切、拼接或图片字段解析阶段。
- 用户补充配置：OpenAI 中转，Base URL 为 `https://ciyuanzhiyan.com/v1`，模型 `gpt-image-2.5-sunburst`，生图路径留空；主题为“地下城副本，Q版手绘，墙壁，火炬，骨头”。随后上游报“对话中没有可用的参考图像”。
- 路径留空会使用 `/images/generations`；默认请求只有 `model`、`prompt`、`n`、`size`。该功能从文字生成新图集，没有发送参考图或对话历史。用户主题和内置槽位规则均不依赖外部原图。
- 尚未取得实际失败请求和完整响应体，附加字段配置也未确认。不能仅凭此正文认定模型选错、提示词超长或需要改用某种协议。
- 中转公开页面为 Sub2API 界面，公开配置未提供文档链接，模型广场未开放，`/v1/models` 需要鉴权。参考开源 Sub2API 在 `dba770d56a0ee0ae5bad1b3dc5e11614d323163c` 的 `openai_images_responses.go`，其 Images 兼容层可把生成请求转为 Responses 图片工具，并区分 `generate` 与 `edit`。这只是定位方向，无法确认该站部署版本、账号路由或工具执行行为。官方文档页面在当前环境访问失败，未据此推断该站的模型能力。

## 本次改动

- 所有图集提示词开头明确要求立即生成并返回图片，避免仅评审规格或输出后续建议。进一步明确“仅根据本次文字从零创建独立图集，无需参考图和历史对话，一致性指新图集内部”。保留用户主题、尺寸、槽位清单和连接拓扑规则。这是提示词层的缓解措施，尚未由真实上游验证效果。
- 对含 FollowUp 的 HTTP 生图错误保留状态码，明确提示“上游返回了文字，未返回图片”，附上有长度限制的文字摘要，并提示核对生图模型和接口路径。
- 成功 HTTP 响应中只有常见聊天/Gemini/Responses 文字字段时，也给出上述说明。存在图片时继续正常处理；未知响应结构保留响应路径提示。
- 不自动执行 FollowUp，不自动重试或切换模型。失败后保留已有图集。
