# Tilemap Generator

一个面向 Mir / V100 风格 2D 游戏的地图生成器。它在浏览器中完成图集生成、素材提取、自动拼图和手工编辑，支持将结果导出为地图 PNG、工程文件，以及 V100 `.map` 和 V3 `.Lib` 素材库。

## 功能

- 生成或上传两张规则图集：按地砖尺寸计算容量的地形图集、4×2 前景物件图集，也可选择旧版 4×4 地砖布局。
- 支持 OpenAI 兼容的生图与视觉接口，也提供无需 API Key 的程序化演示图集。
- 按网格切片地砖，自动将品红背景抠成透明 PNG，并校正地砖边缘。
- 根据地貌提示词、地图尺寸、种子和拼图模式生成可行走的地图布局。
- 在画布中绘制地砖、放置物件、设置阻挡、撤销/重做，并预览碰撞层。
- 导出地图 PNG、PNG + JSON 图集、可恢复的工程 JSON，以及 V100 地图和 Lib 资源。

## 快速开始

需要 Node.js 18 或更高版本。项目没有构建步骤，也不需要安装 npm 依赖。

```bash
node server/dev-server.mjs
```

然后打开 <http://127.0.0.1:5173>。Windows 用户也可以双击 `start-web.bat` 自动启动服务并打开浏览器。可通过 `PORT=5174`（Windows PowerShell 使用 `$env:PORT=5174`）更换端口。

## 使用流程

1. 在“生成两张图集”中填写地貌和风格，设置图集尺寸、地砖槽位大小和布局。点击“生成演示双图集”，或配置 API 后生成/上传地砖图集与前景图集。
2. 进入“提取图集素材”，按保存的布局提取基础材质与方向封边素材，以及 8 个前景物件。输出地砖默认使用生成槽位的中心 3:2 区域，也可选择其他提取尺寸。
3. 在“自动拼图”中设置地图列数、行数、地貌模式、变化度和道路修复选项，生成地图。
4. 在“地图编辑”中使用画笔、橡皮、物件和阻挡工具微调，最后导出 PNG、工程或地图资源。

替换图集或重新提取会清空旧地图和历史记录；重要结果请先导出工程。草稿保存在浏览器 `localStorage`，导出的工程 JSON 可在其他浏览器恢复。

## 地砖容量与封边素材

默认“丰富素材 + 方向封边”布局按 `floor(图集边长 / 地砖槽位边长)²` 计算容量。1024×1024 图集的示例：

| 槽位边长 | 网格 | 素材数 |
| --- | --- | --- |
| 64 px | 16×16 | 256 |
| 96 px | 10×10 | 100 |
| 128 px | 8×8 | 64 |
| 192 px | 5×5 | 25 |

96 指图集中的 96×96 正方形槽位，供游戏使用的中心 3:2 区域提取为 96×64；地图逻辑格仍为 48×32。100 格占据 960×960，四周各留 32 像素，预览网格和裁切按该区域对齐。若服务返回不同分辨率，提取会按比例映射并提示核对网格。

100 格中包含 40 张基础纹理，以及岩壁、岸线、路缘各 20 张方向素材，优先覆盖直边、外角、内角、孤立块、端头和窄线。提示词逐格规定连接方向、背景材质、统一光向和接缝约束。更大容量会补足每类最多 46 个过渡状态，其余空间用于基础变体。

铺地图时只随机选择基础材质，再根据实际八邻域选方向素材；未预画的状态和多材质交会由程序合成，共享边界规则保持一致。选择方向素材作为画笔时，绘制的是该地形类别，朝向随邻格自动匹配。工程与素材 JSON 保留这些规则，PNG 和 Lib 使用同一结果。

方向素材元数据中，`mask` 的第 0–7 位依次对应 N、NE、E、SE、S、SW、W、NW；1 表示该方向连接同类材质。对角连接要求相邻两条直边也连接，255 为全连接基础状态；`backgroundKind` 指定外侧背景。

修改尺寸用于下次生成或上传，已有图集仍按其保存的布局提取。旧的 4×4 图集应在上传前选“旧版 4×4”；已有工程会自动恢复其布局。新提示词需要重新生成地砖图集才能产生新的封边细节；真实生图模型对密集槽位排版及纹理一致性的遵循程度仍需核对。

## Mir 地图资源导出

导出会将网页合成后的地形过渡按 2×2 个逻辑格烘焙成 96×64 像素底砖，并复用像素相同的帧；地图索引引用这些合成帧。碰撞仍逐格保存。

已核对的 selfmir 客户端只在正偶数坐标绘制底砖。为保留原图左上角，导出增加两格不可通行的顶部和左侧边界，原坐标 `(x,y)` 对应导出坐标 `(x+2,y+2)`；宽高分别为 `2 + ceil(原尺寸 / 2) * 2`。奇数尺寸的右侧或底部补一格透明、不可通行区域。例如 48×48 工程导出为 50×50 地图，5×3 工程导出为 8×6。编辑中的工程与 PNG 尺寸保持不变，客户端传送点等坐标需要使用导出坐标。

库号对应已核对的 WemadeMir2 `MapLibs` 配置，Lib 文件放入客户端 `Data/Map/WemadeMir2/`：

| 库号 | 文件名 |
| --- | --- |
| 0 | `Tiles.Lib` |
| 1 | `Smtiles.Lib` |
| 2 | `Objects.Lib` |
| 3–28 | `Objects2.Lib`–`Objects27.Lib` |
| 90 | `Objects_32bit.Lib` |

默认导出 `Tiles.Lib`、`Objects.Lib` 和以工程名命名的 `.map`。地形与前景库号必须不同，前景库号需大于等于 2；其他库号会被拒绝。自定义客户端需核对自己的素材库配置。

地面已通过 Lib 解压、地图索引重建与网页逐像素对比；尚未启动游戏客户端验收。前景物件的缩放、锚点、遮挡及变体选择仍需进一步统一，当前验证不代表整张地图在客户端中的显示验收。

## AI 配置

在页面展开“AI 设置”，填写兼容接口地址、模型和 API Key。Key 仅保存在本机浏览器；开发服务器的 `/proxy` 仅监听 localhost，用于处理浏览器跨域请求。不要把 Key 写入代码、截图或提交记录。未配置 AI 时可使用演示模式和本地上传流程。

## 开发与测试

```bash
node --test server/ai-image.test.mjs server/atlas.test.mjs server/terrain.test.mjs server/exporters.test.mjs
node server/e2e-smoke.mjs
```

第一条命令运行 Node 内置测试。第二条命令需要 Python Playwright、Chromium 和 Pillow，并且要先启动开发服务器；也可以直接运行 `python server/atlas-smoke.py`。测试截图和导出文件写入 `output/atlas-review/`。

## 目录结构

`web/` 是浏览器端应用，`server/` 是本地服务和测试，`docs/superpowers/` 保存设计文档与实现计划，`start-web.bat` 是 Windows 启动脚本。
